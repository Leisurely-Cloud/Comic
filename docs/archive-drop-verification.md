# CBZ / ZIP 拖放阅读验收

日期：2026-10-23。基于现有未提交工作区实施，保留此前书库、阅读状态、批量导入、压缩包阅读和最近记录改动。没有提交、推送或发布，没有操作真实漫画书库、账号或下载任务。

## 使用入口与范围

运行 `start-winui.cmd`，进入“我的书库”，将资源管理器中的单个 `.cbz` / `.zip` 文件拖到页面即可进入阅读器。沿用同一路径的章节、页码、阅读偏好和书签；最近记录仍由阅读器在图片成功显示后保存。

拖动提示标注每次一个文件。目录、多个文件、其他扩展名和无可用绝对路径的项目不会打开，并显示原因；网页链接和纯文本不作为归档接收。拖放只传递用户明确选定的文件路径，不复制、移动、解压或改写源文件。

空书库增加可见的拖入提示；原文件选择器和最近菜单继续可用。

## 异步与数据边界

- `GetStorageItemsAsync` 使用原生拖放 deferral，最终统一完成；只映射最多两个项目，足以拒绝多文件，不批量读取文件路径。
- ViewModel 只验证文件种类、数量、绝对路径和扩展名，不检查归档内容、不读取图片、不授权，也不写入进度、历史或目录书库。
- 阅读器在显式导航后重新校验文件及资源上限，再创建新的归档会话。归档损坏、丢失或读取失败继续使用现有错误提示。
- 已有一个请求时拒绝重复拖放。离开书库时取消，递增请求标识；旧提供方即使忽略取消并迟到返回或报错，也不能返回导航路径、覆盖错误或清除新请求的忙碌状态。
- 书架、标签、删除漫画、清理副本和导入目录的整个异步交互使用可嵌套作用域，开始时取消待处理拖放，结束时才恢复接收。Drop 在返回后再次检查活动页面及交互状态，防止突然切走页面。

只读复核发现首版仅检查书架、压缩包历史和文件选择状态，可能漏掉删除、清理副本及导入对话框；已用统一交互作用域修复，并通过复核。
